# 需求文档

## 1. 应用概述

### 1.1 应用名称
动画大丸家 3.0

### 1.2 应用描述
动画大丸家 3.0 是一款面向短视频创作者、AI 漫剧创作者、条漫创作者的 AI 辅助创作平台。帮助用户完成从选题策划、剧本生成、分镜脚本、图片提示词、视频提示词、图片素材生成、视频素材生成到条漫排版导出的一站式创作流程。

### 1.3 产品定位
多用户创作工具，每个用户拥有独立数据空间，通过后端代理安全管理API Key，确保用户数据隔离和安全性。

## 2. 用户与使用场景

### 2.1 目标用户
- 短视频创作者
- AI 漫剧创作者
- 条漫创作者
- 管理员

### 2.2 核心使用场景
- 用户注册账号并登录系统
- 用户配置个人API Key用于生成功能
- 用户需要快速生成爆款选题并转化为剧本
- 用户需要将剧本拆解为分镜脚本
- 用户需要生成图片和视频素材
- 用户需要将素材排版为条漫并导出
- 用户需要管理声音库并使用TTS生成音频
- 管理员需要管理用户账号、封禁/解封用户、重置用户密码

### 3.2 注册页面

#### 3.2.1 注册表单
- 用户名（必填，3-20个字符，仅支持字母、数字、下划线）
- 密码（必填，8-20个字符，必须包含大小写字母和数字）
- 确认密码（必填，需与密码一致）
- 邮箱（必填，用于密码重置）

#### 3.2.2 注册校验
- 用户名唯一性校验
- 密码强度校验
- 邮箱格式校验
- 邮箱唯一性校验

#### 3.2.3 注册流程
- 用户填写注册信息
- 提交注册请求
- 后端创建用户账号
- 注册成功后自动跳转登录页面

### 3.3 登录页面

#### 3.3.1 登录表单
- 用户名（必填）
- 密码（必填）
- 记住我（选填，勾选后7天内免登录）

#### 3.3.2 登录流程
- 用户输入用户名和密码
- 提交登录请求
- 后端验证用户身份
- 后端校验用户封禁状态
- 返回认证token
- 前端保存token
- 跳转到工作台

#### 3.3.3 登录状态管理
- 使用JWT token进行会话管理
- token有效期为7天
- token过期后自动跳转登录页面
- 支持token刷新机制

### 3.4 密码重置页面

#### 3.4.1 重置流程
- 用户输入注册邮箱
- 系统发送重置链接到邮箱
- 用户点击链接进入重置页面
- 用户输入新密码
- 提交重置请求
- 重置成功后跳转登录页面

#### 3.4.2 安全限制
- 重置链接有效期为30分钟
- 每个邮箱每小时最多发送3次重置邮件

### 3.12 音频制作

#### 3.12.1 页面结构
音频制作页面包含两个Tab：
- 声音库 Tab
- 文本转语音 Tab

#### 3.12.2 声音库 Tab

##### 3.12.2.1 声音列表
- 以卡片形式展示当前用户的所有声音
- 每个卡片显示：声音名称、reference_id、来源标签（手动添加/同步/创建）、是否为默认声音、创建时间
- 支持搜索声音名称
- 支持按来源筛选
- 支持按时间排序

##### 3.12.2.2 手动添加声音
- 点击「手动添加声音」按钮
- 弹出表单：声音名称（必填）、reference_id（必填）、备注（选填）
- 提交后保存到 voice_profiles 表，source 字段标记为 manual

##### 3.12.2.3 同步 Fish Audio 声音模型
- 点击「同步 Fish Audio 声音」按钮
- 选择已配置的 Fish Audio API 配置
- 调用后端 fish-sync-voices EF
- 后端请求 GET /model?self=true 获取声音列表
- 将声音同步到 voice_profiles 表，source 字段标记为 synced
- 保存原始返回数据到 raw 字段
- 同步完成后刷新声音列表

##### 3.12.2.4 上传参考音频创建声音模型
- 点击「上传参考音频创建声音」按钮
- 弹出表单：声音名称（必填）、参考音频文件（必填，支持格式：mp3/wav/m4a）、备注（选填）
- 调用后端 fish-create-voice EF
- 后端请求 POST /model（multipart/form-data）提交音频文件
- 返回的 _id 保存为 reference_id
- 保存到 voice_profiles 表，source 字段标记为 created
- 创建完成后刷新声音列表

##### 3.12.2.5 声音卡片操作
- 设为默认：将当前声音设为默认声音，用于TTS时自动选中
- 复制 reference_id：复制声音的 reference_id 到剪贴板
- 用于 TTS：跳转到文本转语音 Tab 并自动选中该声音
- 编辑：修改声音名称和备注
- 删除：删除声音（需二次确认）

#### 3.12.3 文本转语音 Tab

##### 3.12.3.1 输入参数
- 文本内容（必填，多行文本框）
- 声音选择（必填，从声音库下拉选择）
- 使用模型（必填，从已配置的音频生成模型中选择）
- 语速（选填，范围0.5-2.0，默认1.0）
- 音调（选填，范围-12到12，默认0）
- 是否保存到素材库（选填，默认勾选）

##### 3.12.3.2 声音选择优化
- 优先从声音库下拉选择声音
- 下拉列表显示：声音名称 + reference_id 前8位
- 默认选中标记为默认的声音
- 若声音库为空，显示空状态引导提示：「声音库为空，请先添加声音」
- 空状态下方显示三个操作按钮：「手动添加声音」「同步 Fish Audio 声音」「上传参考音频创建声音」

##### 3.12.3.3 生成按钮禁用逻辑与提示
- 文本内容为空时：禁用生成按钮，按钮旁显示提示「请输入文本内容」
- 未选择模型时：禁用生成按钮，按钮旁显示提示「请选择音频生成模型」
- 未选择声音时：禁用生成按钮，按钮旁显示提示「请选择声音」
- 未配置 API 时：禁用生成按钮，按钮旁显示提示「请先配置音频生成 API」
- 所有条件满足时：启用生成按钮，清除提示

##### 3.12.3.4 生成流程
- 点击生成按钮
- 调用后端音频生成接口
- 传递参数：文本内容、reference_id、模型配置、语速、音调
- 生成完成后返回音频文件地址
- 若勾选保存到素材库，自动保存音频到素材库
- 显示音频播放器，支持播放、下载、复制地址

##### 3.12.3.5 历史记录
- 展示当前用户最近生成的音频列表
- 每条记录显示：文本摘要、使用声音、生成时间、音频时长
- 支持播放、下载、删除、复制地址

## 4. 业务规则与逻辑

### 4.1 用户认证规则
- 未登录用户只能访问注册、登录、密码重置页面
- 已登录用户可访问所有功能页面
- token过期后自动跳转登录页面
- 用户退出登录后清除本地token

### 4.2 数据隔离规则
- 所有数据表必须包含 user_id 字段
- 所有数据表必须启用 RLS（Row Level Security）保护
- RLS 策略：用户只能访问自己的数据
- 数据表包括：projects、topics、scripts、storyboards、assets、api_configs、model_catalog、function_model_bindings、prompt_templates、video_tasks、comic_drafts、voice_profiles

### 4.3 API Key管理规则
- 用户在模型配置页面添加API Key
- API Key在后端加密存储
- 前端不暴露API Key明文
- 所有涉及API Key的请求必须通过后端代理
- 后端在调用第三方API时解密API Key

### 4.4 生成功能调用规则
- 用户发起生成请求时，前端传递用户token和生成参数
- 后端验证用户身份
- 后端根据用户ID获取对应的API配置
- 后端解密API Key
- 后端代理调用第三方API
- 后端返回生成结果
- 生成记录保存到用户数据空间

### 4.5 项目关联规则
- 所有内容必须关联到具体项目
- 删除项目需二次确认
- 项目删除后关联内容一并删除

### 4.6 AI生成流程
1. 选择功能
2. 选择项目
3. 选择模型
4. 选择提示词模板
5. 填写参数
6. 构建完整提示词
7. 前端发送请求到后端
8. 后端验证用户身份
9. 后端获取用户API配置
10. 后端解密API Key
11. 后端代理调用模型
12. 后端解析结果
13. 后端返回结果
14. 前端展示结果
15. 保存结果到用户数据空间

### 4.7 默认模型规则
- 未选择模型时使用功能绑定默认模型
- 无可用模型时引导用户去模型配置

### 4.8 提示词变量替换规则
- 在调用模型前将模板中的变量替换为实际值
- 变量格式：{{变量名}}
- 必填变量未填写时提示用户

### 4.9 分镜素材绑定规则
- 分镜可绑定1张主图
- 分镜可绑定多张候选图
- 分镜可绑定1个主视频
- 分镜可绑定多个候选视频

### 4.10 声音库管理规则
- 所有声音必须关联到具体用户
- 声音库数据强制 user_id 隔离
- 声音来源分为三类：manual（手动添加）、synced（同步）、created（创建）
- 每个用户只能有一个默认声音
- 设置新默认声音时自动取消原默认声音
- 删除默认声音时需提示用户重新设置默认声音

### 4.11 Fish Audio 声音同步规则
- 调用后端 fish-sync-voices EF
- 后端校验用户身份
- 后端根据用户ID获取API配置
- 后端解密 API Key
- 后端请求 GET /model?self=true
- 将返回的声音列表 upsert 到 voice_profiles 表
- 保存原始返回数据到 raw 字段（JSONB格式）
- 同步时根据 reference_id 判断是否已存在，存在则更新，不存在则新增

### 4.12 上传参考音频创建声音规则
- 调用后端 fish-create-voice EF
- 后端校验用户身份
- 后端接收音频文件
- 后端根据用户ID获取API配置
- 后端解密 API Key
- 后端请求 POST /model（multipart/form-data）提交音频文件
- 返回的 _id 保存为 reference_id
- 保存到 voice_profiles 表，source 字段标记为 created

### 4.13 TTS 生成规则
- 必须选择声音库中的声音
- 必须选择音频生成模型
- 必须填写文本内容
- 调用后端音频生成接口时传递 reference_id
- 后端验证用户身份
- 后端根据用户ID获取API配置
- 后端解密API Key
- 后端代理调用音频生成API
- 生成完成后若勾选保存到素材库，自动保存音频

### 4.14 数据存储规则
- 使用Supabase存储数据
- 需要创建以下数据库表：users、projects、topics、scripts、storyboards、assets、api_configs、model_catalog、function_model_bindings、prompt_templates、video_tasks、comic_drafts、voice_profiles、profiles
- users 表结构：
  + id（主键）
  + username（用户名，唯一）
  + password_hash（密码哈希）
  + email（邮箱，唯一）
  + created_at（创建时间）
  + updated_at（更新时间）
- profiles 表结构：
  + id（主键，关联 users.id）
  + user_id（用户ID，必填）
  + role（角色：user/admin，默认user）
  + is_banned（是否封禁，布尔值，默认false）
  + ban_reason（封禁原因，选填）
  + created_at（创建时间）
  + updated_at（更新时间）
- voice_profiles 表结构：
  + id（主键）
  + user_id（用户ID，必填）
  + name（声音名称，必填）
  + reference_id（Fish Audio 声音模型ID，必填）
  + source（来源：manual/synced/created，必填）
  + raw（原始返回数据，JSONB格式，选填）
  + is_default（是否为默认声音，布尔值）
  + remark（备注，选填）
  + created_at（创建时间）
  + updated_at（更新时间）
- 所有数据表必须启用 RLS（Row Level Security）保护
- RLS 策略：用户只能访问自己的数据

### 4.15 管理员权限规则
- 管理员角色通过 profiles.role = 'admin' 判断
- 管理员可访问管理员后台
- 管理员可查看所有用户信息
- 管理员可封禁/解封任意用户
- 管理员可重置任意用户密码
- 普通用户无法访问管理员后台
- 普通用户无法执行管理员操作

### 4.16 用户封禁规则
- 封禁状态保存在 profiles.is_banned 字段
- 封禁原因保存在 profiles.ban_reason 字段
- 用户登录时后端校验 is_banned 状态
- 被封禁用户登录被拒绝，返回封禁提示和原因
- 被封禁用户无法使用任何功能
- 解封后用户恢复正常使用权限

### 4.17 密码重置规则
- 管理员可为任意用户重置密码
- 重置方式：生成随机密码/设置指定密码
- 随机密码长度为8位，包含大小写字母和数字
- 重置后用户需用新密码登录
- 新密码仅在重置成功后显示一次

## 5. 后端 Edge Functions 说明

### 5.1 auth-register
- 功能：用户注册
- 请求方式：POST
- 请求参数：username（用户名）、password（密码）、email（邮箱）
- 处理流程：
  1. 校验用户名、密码、邮箱格式
  2. 校验用户名和邮箱唯一性
  3. 密码哈希加密
  4. 创建用户记录
  5. 创建 profiles 记录，role 默认为 user，is_banned 默认为 false
  6. 返回注册结果

### 5.2 auth-login
- 功能：用户登录
- 请求方式：POST
- 请求参数：username（用户名）、password（密码）
- 处理流程：
  1. 校验用户名和密码
  2. 验证密码哈希
  3. 查询 profiles 表校验封禁状态
  4. 若 is_banned 为 true，拒绝登录并返回封禁提示和原因
  5. 生成JWT token
  6. 返回token和用户信息

### 5.3 auth-reset-password
- 功能：密码重置
- 请求方式：POST
- 请求参数：email（邮箱）、new_password（新密码）、reset_token（重置令牌）
- 处理流程：
  1. 校验重置令牌有效性
  2. 校验新密码格式
  3. 密码哈希加密
  4. 更新用户密码
  5. 返回重置结果

### 5.4 proxy-generate
- 功能：代理生成请求
- 请求方式：POST
- 请求参数：function_type（功能类型）、model_id（模型ID）、prompt（提示词）、parameters（生成参数）
- 处理流程：
  1. 校验用户身份
  2. 根据用户ID和model_id获取API配置
  3. 解密API Key
  4. 构建第三方API请求
  5. 代理调用第三方API
  6. 解析返回结果
  7. 保存生成记录到用户数据空间
  8. 返回生成结果

### 5.5 fish-sync-voices
- 功能：同步 Fish Audio 声音模型到声音库
- 请求方式：POST
- 请求参数：api_config_id（API配置ID）
- 处理流程：
  1. 校验用户身份
  2. 根据 api_config_id 获取 API 配置
  3. 解密 API Key
  4. 请求 GET /model?self=true
  5. 解析返回的声音列表
  6. 根据 reference_id 判断是否已存在
  7. 存在则更新，不存在则新增到 voice_profiles 表
  8. 保存原始返回数据到 raw 字段
  9. 返回同步结果

### 5.6 fish-create-voice
- 功能：上传参考音频创建 Fish Audio 声音模型
- 请求方式：POST
- 请求参数：api_config_id（API配置ID）、name（声音名称）、audio_file（音频文件）、remark（备注，选填）
- 处理流程：
  1. 校验用户身份
  2. 根据 api_config_id 获取 API 配置
  3. 解密 API Key
  4. 构建 multipart/form-data 请求
  5. 请求 POST /model 提交音频文件
  6. 解析返回的 _id
  7. 保存到 voice_profiles 表，reference_id 为返回的 _id，source 标记为 created
  8. 返回创建结果

### 5.7 audio-provider-test
- 功能：测试音频 API 配置是否有效
- 请求方式：POST
- 请求参数：api_config_id（API配置ID）
- 处理流程：
  1. 校验用户身份
  2. 根据 api_config_id 获取 API 配置
  3. 解密 API Key
  4. 发送测试请求验证 Key 有效性
  5. 返回测试结果

### 5.8 admin-ban-user
- 功能：管理员封禁用户
- 请求方式：POST
- 请求参数：user_id（用户ID）、ban_reason（封禁原因，选填）
- 处理流程：
  1. 校验请求者身份
  2. 校验请求者是否为管理员（profiles.role = 'admin'）
  3. 使用 Supabase Auth Admin API 更新用户封禁状态
  4. 更新 profiles 表，设置 is_banned = true，保存 ban_reason
  5. 返回封禁结果

### 5.9 admin-unban-user
- 功能：管理员解封用户
- 请求方式：POST
- 请求参数：user_id（用户ID）
- 处理流程：
  1. 校验请求者身份
  2. 校验请求者是否为管理员（profiles.role = 'admin'）
  3. 使用 Supabase Auth Admin API 更新用户封禁状态
  4. 更新 profiles 表，设置 is_banned = false，清空 ban_reason
  5. 返回解封结果

### 5.10 admin-reset-password
- 功能：管理员重置用户密码
- 请求方式：POST
- 请求参数：user_id（用户ID）、reset_type（重置方式：random/custom）、new_password（新密码，reset_type=custom时必填）
- 处理流程：
  1. 校验请求者身份
  2. 校验请求者是否为管理员（profiles.role = 'admin'）
  3. 若 reset_type = random，生成8位随机密码
  4. 若 reset_type = custom，使用传入的 new_password
  5. 使用 Supabase Auth Admin API 更新用户密码
  6. 返回重置结果和新密码

### 5.11 admin-get-users
- 功能：管理员获取用户列表
- 请求方式：GET
- 请求参数：page（页码）、page_size（每页数量）、search（搜索关键词，选填）、role_filter（角色筛选，选填）、status_filter（状态筛选，选填）
- 处理流程：
  1. 校验请求者身份
  2. 校验请求者是否为管理员（profiles.role = 'admin'）
  3. 使用 Supabase Auth Admin API 获取用户列表
  4. 关联 profiles 表获取角色和封禁状态
  5. 根据筛选条件过滤用户
  6. 分页返回用户列表

## 6. 安全要求

### 6.1 用户认证安全
- 密码必须哈希加密存储
- 使用JWT token进行会话管理
- token有效期为7天
- token过期后自动跳转登录页面
- 支持token刷新机制

### 6.2 数据隔离安全
- 所有数据表强制 user_id 隔离
- 启用 RLS（Row Level Security）保护
- RLS 策略：用户只能访问自己的数据

### 6.3 API Key 安全
- API Key 在后端加密存储
- API Key 只在后端解密
- 前端不暴露 API Key
- 后端 Edge Functions 负责所有 API 调用

### 6.4 请求安全
- 所有生成请求必须验证用户身份
- 使用请求签名机制防止篡改
- 实现速率限制防止滥用

### 6.5 文件上传安全
- 限制上传文件类型：mp3/wav/m4a
- 限制上传文件大小
- 后端校验文件格式

### 6.6 CORS跨域安全
- 配置CORS白名单
- 仅允许授权域名访问

### 6.7 管理员权限安全
- 管理员操作必须验证 profiles.role = 'admin'
- 使用 Supabase Auth Admin API 的 service role key 仅在后端 Edge Functions 中使用
- 前端不暴露 service role key
- 管理员操作记录日志
- 非管理员访问管理员后台时拒绝访问

## 7. 异常与边界情况

| 异常场景 | 处理方式 |
|---------|----------|
| 用户名已存在 | 提示用户用户名已被占用，建议更换 |
| 邮箱已存在 | 提示用户邮箱已被注册，建议使用其他邮箱或找回密码 |
| 密码强度不足 | 提示用户密码必须包含大小写字母和数字，长度8-20个字符 |
| 登录失败 | 提示用户用户名或密码错误 |
| 被封禁用户登录 | 拒绝登录，提示用户账号已被封禁，显示封禁原因 |
| token过期 | 自动跳转登录页面，提示用户重新登录 |
| 未登录访问功能页面 | 自动跳转登录页面 |
| API Key未配置 | 引导用户去模型配置页面添加API Key |
| API Key无效 | 提示用户检查API Key是否正确，提供重新配置入口 |
| API连接失败 | 提示用户检查网络连接和API配置，提供重试按钮 |

## 8. 验收标准

1. 用户访问注册页面，填写用户名「testuser」、密码「Test1234」、确认密码「Test1234」、邮箱「test@example.com」，点击注册，系统创建账号并跳转登录页面
2. 用户在登录页面输入用户名「testuser」、密码「Test1234」，点击登录，系统验证身份并返回token，跳转到工作台
3. 用户进入模型配置页面，添加API配置，填写配置名称「OpenAI」、API提供商「OpenAI」、Base URL、API Key，点击保存，系统加密存储API Key
4. 用户创建项目，填写项目名称「AI漫剧测试」、内容类型「AI漫剧」、目标平台「抖音」、默认画面比例「9:16」
5. 用户进入爆款选题生成，选择项目「AI漫剧测试」，输入关键词「职场逆袭」，生成数量「5条」，点击生成，系统通过后端代理调用API，返回5条选题并保存到用户数据空间
6. 用户选择其中一条选题，点击「一键进入剧本生成」，系统自动填充选题信息，用户设置剧本时长「60秒」，点击生成，系统通过后端代理调用API，返回完整剧本并保存到用户数据空间
7. 用户点击「一键进入分镜生成」，系统自动填充剧本内容，用户设置分镜数量「8个」，点击生成，系统通过后端代理调用API，返回8个分镜并保存到用户数据空间
8. 用户选择第1个分镜，点击「一键生成图片」，系统通过后端代理调用图片生成API，返回图片并自动绑定到分镜，保存到用户数据空间
9. 用户进入音频制作页面，点击「同步 Fish Audio 声音」，选择已配置的 Fish Audio API，系统调用后端 fish-sync-voices EF，后端代理调用Fish Audio API，同步声音列表到用户声音库
10. 用户切换到文本转语音 Tab，从声音库选择声音，输入文本内容，选择音频生成模型，点击生成，系统通过后端代理调用音频生成API，返回音频文件并保存到用户素材库
11. 管理员登录系统，侧边栏显示「管理员后台」入口，点击进入管理员后台
12. 管理员在用户列表中搜索用户「testuser」，点击「封禁」按钮，填写封禁原因「违规操作」，确认封禁，系统更新用户封禁状态
13. 被封禁用户「testuser」尝试登录，系统拒绝登录并提示「账号已被封禁，原因：违规操作」
14. 管理员在用户列表中找到用户「testuser」，点击「解封」按钮，确认解封，系统更新用户封禁状态
15. 用户「testuser」重新登录，系统验证身份并返回token，跳转到工作台
16. 管理员在用户列表中找到用户「testuser」，点击「重置密码」按钮，选择「生成随机密码」，系统生成新密码并显示，管理员将新密码告知用户
17. 用户「testuser」使用新密码登录，系统验证身份并返回token，跳转到工作台
18. 用户退出登录，系统清除本地token，跳转到登录页面
